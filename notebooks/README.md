# Colab: one-billion-position training

Open `Train_Sanskrit_1B_Colab.ipynb` in Google Colab and select **Runtime → Run all**. Choose a GPU and authorize Google Drive when prompted. The notebook uses a public, fixed repository revision and downloads the verified 2,000-step GitHub candidate automatically. It starts a new 1-billion-**additional non-padding input position** run; the QA prompt positions are counted as input but masked from the loss. Loss-bearing token positions are tracked separately. It does not represent one billion unique tokens.

The training mix is small and repeatedly sampled: the five original-site Amarahasa book extracts, agent-authored Q&A and single-answer SktQA Ramayana Q&A. They are not independently reviewed, source-specific rights need confirmation, and SktQA is a benchmark, not a held-out test for this run. Repetition can cause overfitting; the model's correctness and grammar retention remain unproven. The 10,000-Q&A target is still incomplete. See `reports/automated_book_qa_plan.md` for provenance and caveats.

Checkpoints are saved every five minutes to `MyDrive/Sanskrit-LLM/colab-1b` with optimizer, random states, counters, a data fingerprint and SHA-256. Files are retained, about 119 MB per save, and can fill Drive. Colab may disconnect or exhaust its quota before reaching the target; rerun the notebook in a GPU runtime to resume the latest verified checkpoint. Interruptions can lose work since the last save. Do not run multiple sessions on the same folder. GPU usage may incur charges. A corrupted or incomplete latest checkpoint produces an error rather than silently reverting. Neither training nor deployment occurs until you run the notebook, and it never auto-deploys the result.
