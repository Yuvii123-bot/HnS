# SANĀTAN AI: conversation contamination investigation

Status: **investigation and one future-data bug fix only; not a demonstrated model fix**. No training run was stopped, modified, or restarted and no new model was deployed for this investigation. The production checkpoint investigated is commit `f39a1e4`, step 50,600, nominal 207,257,600 token positions. The GitHub 250M run is an independent in-progress continuation and is pinned to its own earlier code/corpus. Results below are diagnostic, not a 250-question held-out evaluation.

## Evidence and mechanisms

1. **Wrong labels in generated supervision (confirmed).** In `build_curriculum.py::time_rows`, four fixed questions and four answers were independently sampled. Thus, for each question, three answers out of four were unrelated. On one reconstructed local corpus chunk (`part_001.txt`), 5,884 of 7,806 such rows were incorrectly paired. The reconstruction is not a byte-for-byte verification of the GitHub release corpus, although it uses the same generator. The released GitHub run used the pre-fix generator; changing the source now does not alter its already encoded corpus.
2. **Validation leakage (confirmed for reconstructed corpus).** Of 1,269 distinct rows in its `val.txt`, 708 reoccurred exactly in just `part_001.txt`. Validation was sampled only from the first randomly generated part while later parts reuse fixed pools and generated templates. This is not a held-out estimate; exact matching also misses paraphrase and source-family leakage. The old 500-question test should remain disabled.
3. **Substantial grammar exposure and unconditioned prose (confirmed, causality not proved).** In the same 195,123-row chunk, 40,932 contained `शब्दस्य` and 36,722 had neither user nor assistant markers. Untagged lines include grammar prose from `build_lexicon_prose.py`, which emits standalone sentences such as `प्रथमा विभक्तौ एकवचने ...` and does not retain the paragraph's subject on every line. These counts are line counts, not token shares or evidence that grammar itself should be removed. Grammar is useful; the concern is mixing unconditioned prose with supervised dialogue without proper source/role conditioning.
4. **Boundary mismatch (confirmed).** `encode_stream.py` appends EOS after each line. `TokenDataset` samples arbitrary contiguous windows and causal attention does not reset at EOS, so tokens can attend across unrelated examples. The loss also trains every token, including user text and unconditioned prose, rather than isolating assistant responses. In chat inference `api/index.py` defaults to `max_lines=2`; `numpy_lm.py::sample` treats EOS as a line break and continues generation until a second EOS. This can expose a subsequent unrelated training-style continuation. The observed bug is possible, but its share of live failures has not been measured.
5. **Repeated random windows across timed segments (confirmed by code).** `TokenDataset.__init__` seeds its NumPy generator with 1234, `train_model.py` restarts a new dataset each time, and GitHub's `github_train_segment.py` starts a new trainer process each hour. Dataset RNG state is not in the checkpoint. Each fresh segment thus replays the same sequence of random start positions for a given dataset, reducing effective data diversity. Reported token counts are processed positions, not unique tokens. The exact resulting duplication rate has not been measured. This is independent of whether the optimizer state is restored.
6. **Architecture, tokenization and decoding (observations).** The model is a ~9.9M-parameter causal transformer with 4,000 akṣara-BPE vocabulary items, RoPE, tied embeddings and a phonological-feature projection. Special role tags and EOS have dedicated tokens. Six diagnostic prompts all encoded with zero unknown tokens; that is not a general vocabulary audit. Default decoding is stochastic (temperature 0.85, top-k 40, top-p 0.95, repetition penalty 1.15). These settings can change the error rate but do not explain or repair wrong labels. API rejects Latin input, so translation requests involving Latin text are not currently supported. Multi-turn prompts retain up to six supplied turns and are token-truncated to fit the 512-token context; arbitrary truncation can remove context or role boundaries.
7. **Weak alignment (observed, not a quantified attribution).** At step 50,600, production-model code, greedy temperature 0, 55 maximum new tokens and default two-line behavior produced: `भवतः नाम किम्?` → `मम नाम चन्द्रः अस्ति।`; `भवान् कुत्र वसति?` → `अहं ग्रामे निवसामि।`; `गौः किं खादति?` → `गौः दुग्धं ददाति।`; `सूर्यः कुत्र उदेति?` → `सूर्यः पूर्वस्यां दिशि उदेति।`; `रामशब्दस्य षष्ठीविभक्तौ एकवचनरूपं किम्?` → `रामस्य।`; `अहं विद्यालयं गच्छामि। किं करोमि?` → `आम्, अहं विद्यालयं गच्छामि।`. This small, non-held-out smoke test shows both capabilities and irrelevant answers, not performance rates. Personal-answer variants are not inherently wrong merely because they differ from a preferred name or location.
8. `build_chat_data.py` explicitly pairs adjacent corpus lines rather than validated questions and answers. Its presence is evidence of a historical data-construction risk, not proof that these rows entered the current 250M run. Trace data provenance before filtering.

## Change made

Future builds of `build_curriculum.py` select each fixed time question together with its correct answer. `tests/test_curriculum_time_alignment.py` checks 10,000 generated examples. `scripts/audit_conversation_corpus.py` reproduces the aggregate audit and reports exact validation overlap. Neither changes or deletes grammar data. Existing encoded data and weights are unchanged. Other arithmetic, morphology, prose and lexicon correctness require systematic expert/source review; no claim of comprehensive correction is made.

## Required next phase (not yet completed)

- Preserve the complete GitHub base checkpoint, optimizer and checksums; record training run, corpus hash, tokenizer hash, step, all hyperparameters, and source licensing. Do not overwrite the running job or production release. Fix RNG resume and segment seeding for a **separate** continuation; audit any effect on reproducibility.
- Design an expert-reviewed, source-traceable, balanced corpus for conversation, knowledge, explicit grammar, translation and reasoning, with genuine multi-turn state. Include contrastive task pairs without relying on keyword routing. Keep verified grammar rehearsal and grammar-family holdouts; reject contradictory pairs, broken morphology and unattributed or incompatible material. Use explicit line and turn boundaries and response-only loss or packed examples with attention isolation. Avoid splitting correlated templates, entities or sources across training and test.
- Build at least 50 independently reviewed examples for each of conversation, knowledge, grammar, multi-turn and reasoning (250 minimum), disjoint from the *actual* pretraining, continuation and fine-tuning corpora at exact, normalized, template, entity and semantic/source levels. Lock the test set before tuning; have native/Sanskrit reviewers validate references and acceptable variants. Inspect inference preprocessing, EOS/role boundaries and deterministic seeded settings. A 500-question end-of-run test is a separate outstanding requirement.
- Compare frozen base and separately fine-tuned checkpoints on identical prompts, histories and decoding seeds. Store per-item outputs and blinded human assessments of relevance, grammar correctness, semantic accuracy, unwanted grammar injection, coherence and multi-turn consistency, with denominators and uncertainty. Calibrate independent raters; record disagreements. Assess explicit grammar items separately so less grammar in ordinary chat is not mistaken for preserved grammar capability.
- Pre-register promotion thresholds and a grammar non-inferiority margin, and require review of failure cases and regressions. Retain the original deployment and complete optimizer checkpoint for rollback. Do not deploy a candidate until the comparison passes; if the evidence is insufficient, report it as such.
