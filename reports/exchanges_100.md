# 100 basic exchanges in conversation

Set: `data/conv_eval_100.jsonl` — 100 exchanges, 14 categories, 22 of them
multi-turn. In a multi-turn item every prior assistant turn is generated by the
model itself, so the conversation drifts the way a real one does.

Harness: `scripts/eval_exchanges.py`. An item passes only if the reply contains
an accepted fragment **and** passes rubric-independent checks (Devanagari only,
non-empty, no degenerate repetition, finished sentence).

## Result on the deployed model

**72/100 = 72.0 %**

Split by what kind of exchange it is:

| slice | score |
|---|---|
| conversational exchanges (greeting, identity, wellbeing, thanks, apology, help, farewell, language policy, multi-turn) | **60/72 = 83.3 %** |
| knowledge tasks (arithmetic, time/date, declension, vocabulary, dharma, reasoning) | 12/28 = 42.9 % |
| prompts the model has seen in training | 23/23 = 100 % |
| prompts never seen | 49/77 = 63.6 % |
| never seen, conversational only | 41/53 = 77.4 % |

The last two rows are the honest ones: on phrasing it has not memorised, the
model is right about three times in four when the exchange is conversational,
and under half the time when it needs a fact or a computation.

### The failures, verbatim

Conversational — all intent confusions, not ignorance:

| prompt | reply |
|---|---|
| किं समाचारः? (what's the news) | आङ्ग्लं न जानामि। मम भाषा संस्कृतम् एव। |
| अहं नूतनः अस्मि (I'm new) | धन्यवादः। किं पृच्छति भवान्? |
| भवत्याः उपकारः (your kindness) | सनातनी इति मम नाम। |
| अहं त्रुटिं कृतवान् (I made a mistake) | आम्, करोमि। किं पृच्छति भवान्? |
| कथं पठामि? (how do I study?) | मम नाम सनातनी। |

Multi-turn — the model answers the *previous* turn instead of the current one,
which is the clearest structural weakness found:

| context | final turn | reply |
|---|---|---|
| क्षम्यताम् → न दोषः | धन्यवादः | न दोषः। क्षमा न अपेक्षिता। (repeats) |
| शुभा रात्रिः → शुभरात्रिः शुभं स्वप्नम् | पुनः मिलामः | न दोषः। क्षमा न अपेक्षिता। |
| भवत्याः उत्तरं रम्यम् → अनुगृहीता अस्मि | अधिकं वद | अर्थः इति पदस्य अपरः पर्यायः मरुत्। |

Knowledge — the model produces the right *shape* with the wrong content:

| prompt | reply | truth |
|---|---|---|
| पञ्च अधिकं त्रीणि कति? (5+3) | ईषत् इति पदस्य अपरः पर्यायः नभः। | अष्ट |
| राम इति शब्दस्य चतुर्थी एकवचनं किम्? | मम नाम सनातनी। | रामाय |
| गच्छति इति पदस्य धातुः कः? | गौः इति पदस्य अपरः पर्यायः धरा। | गम् |

## Three attempts to train it better — all of them failed

Data: `scripts/build_exchange_data.py` (greetings + arithmetic generated from
addition/subtraction tables + declension paradigms + roots + synonyms + time +
multi-turn flows + scrubbed replay). Eval prompt strings are excluded from
training by an assertion.

| round | data | steps | score | unseen |
|---|---|---|---|---|
| deployed (r10) | — | — | **72.0 %** | 63.6 % |
| ex13 | +arithmetic +grammar, replay 6000 | 900 | 65.0 % | 55.8 % |
| ex14 | +flows +grammar, replay 6000 | 800 | 71.0 % | 62.3 % |
| ex15 | +flows +grammar, replay 3000, greet ×20 | 800 | 68.0 % | 58.4 % |

ex14 is the informative one: grammar 1/8 → 4/8 and multi-turn 15/22 → 18/22, but
thanks 7/8 → 5/8, dharma 5/6 → 3/6, help 5/6 → 4/6 and language 4/4 → 3/4. The
gains and losses cancel. The 9.9 M model is at its capacity for this data: each
new competence is bought with another.

**Arithmetic is not learnable by this model at this size.** With 780 arithmetic
rows in the mix it still answered 5+3 as द्वादश and 9+9 as पंचदश — it learned the
sentence frame (मिलित्वा … भवन्ति) and never learned to add. That is not a data
volume problem that another round would fix.

## What this means

The deployed checkpoint stays as it is; nothing was redeployed, and the greeting
score is unchanged at 43/44. The realistic reading:

* **Conversation it has been taught: 83 %, and 77 % on unseen phrasing.** Good,
  not clean, and the residual is intent confusion on unusual phrasings.
* **Multi-turn is the real structural gap** (15/22): with a history in the
  prompt, the model often continues the previous exchange. Training flows helped
  (+3) but cost elsewhere. This needs more multi-turn data than 32 flows, or an
  architecture that marks turn boundaries explicitly.
* **Facts and arithmetic are out of reach** for a 9.9 M parameter model trained
  on this much data. Arithmetic should be a tool call, not a generation task.

## Reproduction

```bash
python3 scripts/eval_exchanges.py --bundle serve --label deployed   # the deployed bundle
python3 scripts/eval_exchanges.py --checkpoint artifacts/ex14/latest.pt --label ex14
python3 scripts/build_exchange_data.py --repeat-greet 16 --repeat-exchange 6 \
        --repeat-flow 36 --replay-lines 6000 --skip arithmetic --out data/exchange_mix2
```
