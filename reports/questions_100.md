# 100 basic questions to the deployed model

Model: the live bundle in `serve/` (9,896,544 parameters, the checkpoint serving
`sanskrit-llm.vercel.app`). 100 questions, greedy decoding, one reply each.

```
python3 scripts/eval_exchanges.py --bundle serve \
        --eval data/questions_100.jsonl --label questions_deployed
```

## Result

**43/100 = 43.0 %** correct, on a rubric I tightened after
inspecting the answers. The first run scored 54/100, but 11 of those passes were
my own rubric being loose — a bare `न` matching inside `अहं मानुषी न`, `पुष्पम्`

## What the failures are

**1. Grammar production is absent (0/15).** Every question here asks the model to
*produce* a form — dative singular of राम, root of गच्छति, feminine of बालकः. The
training data taught case *identification* (`रामः इति पदं कस्यां विभक्तौ?` →
`प्रथमायाम्`) but never production, so the model has no mapping to learn:

| question | reply | truth |
|---|---|---|
| राम इति शब्दस्य चतुर्थी एकवचनं किम्? | मम नाम सनातनी। | रामाय |
| गच्छति इति पदस्य धातुः कः? | गौः इति पदस्य अपरः पर्यायः धरा। | गम् |
| अश्वः इति शब्दस्य स्त्रीलिङ्गं किम्? | अशीतिः इति पदस्य अपरः पर्यायः नभः। | अश्वा |

**2. Arithmetic is absent (0/10), including counting.** This is the same finding as
the 100-exchange test: with 780 arithmetic rows in a training mix it still answered
5+3 as द्वादश. It has the sentence frame `मिलित्वा … भवन्ति` and no computing.

**3. Intent confusion when the question is worded unusually.** Asked `हिमं किम्?`
it answered `आम्। अहं संस्कृतं जानामि…`; asked `दिशः कति सन्ति?` it answered the
revision of an unknown prompt (`चिन्ता मा। अहं विवृणोमि।`); asked `सूर्ये अस्तं गते`
it answered a help offer. The word cues it learned are narrow.

**4. Glossary is the one area that generalises.** 13/15 without any prompt being seen
verbatim: it has the *pattern* `X इति पदस्य अर्थः` → `X इति पदस्य पर्यायः Y`, which is
the sort of transfer the other categories lack. Two of its three misses are a wrong
gloss (`ज्ञानम्` → its opposite `अज्ञानम्`) rather than a broken pattern.

## What would fix each area

- **Grammar (0/15)**: systematic paradigm drills — the 5 declensions × 3 numbers ×
  8 cases generated from tables, taught as production pairs. `build_exchange_data.py`
  already generates these; one round on them moved declension from 1/8 to 4/8.
- **Numbers (0/10)**: not a data problem at this size. A calculator in the API —
  parse the two numbers, compute, return the Sanskrit word.
- **Intent confusion**: the same deterministic router recommended before. The cue
  words are already known; a pattern table makes them exact.
- **Vocabulary (13/15)**: already working; extend the glossary.
